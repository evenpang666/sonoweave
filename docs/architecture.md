# 流式识别、缓存与校准

1. 每 50 ms 读取系统音频。约 0.9 秒的语音窗口开始首次识别；之后约每 0.55 秒提交一个包含当前句子完整音频的新窗口，不必等整句说完。
2. 启动时即开始采集音频，采集、识别和翻译分别在后台运行。**原文缓存持续增长**：新句子追加，当前句子的识别修订替换其末尾草稿；静音和分窗不会清空前文。缓存最多保留约 8000 字符或 96 段。
3. 每次从原文缓存取最近最多 3 段、约 640 字符构成翻译窗口。段落内部先按句子和较长从句拆成约不超过 240 字符的片段；每句最多参考前两句、约 320 字符的原文。字符数仅用于预分段，真正调用模型前还会按实际 token 数做预算，见下文。原文、语言及有效前文未变的完整片段直接复用，避免反复重译增长中的整段音频；参考前文与待翻译文本分开。
4. **译文缓存持续追加**，通过原文段落编号保持对应关系；修订只替换对应段落，不反复追加同一句话。前面的译文继续留在内存中，窗口显示缓存末尾最多 4 行字幕，自动向后滚动。译文缓存也限制为约 8000 字符或 96 段。翻译待处理队列只保留原文缓存的最新快照，但缓存本身保留前文。
5. 连续静音约 350 ms 后确认当前识别窗口，识别继续等待新语音。连续讲话超过 15 秒时携带约半秒重叠音频进入下一窗，并在原文缓存去除明确来自该重叠的重复词，减少截断边界遗漏。超过 20 秒的停顿或源语言变化会隔断翻译上下文，原文缓存仍保留。切换目标语言会清空旧语言的译文缓存并重新翻译最近的原文窗口。
   源语言判定不再被最初不到一秒的片段锁定：积累约 2.5 秒后才确认，连续音频跨窗沿用稳定语言，并约每 3 秒复核；较弱的语言变化判断需要重复确认。超过 20 秒的停顿后重新检测。这能减少短片段误判整窗语言的问题，但切换语种时仍可能需要几秒校准。
6. 优先处理最新段落，已校验的句子可以先显示，不必等待整个最近窗口完成。后台再补齐较早段落；不会在处理中把已显示的完整段落退回到第一句话。旧段落推理落后新段落超过约 1.5 秒时可取消，语言切换也会取消旧任务。识别先使用 beam 1；连续约 1.5 秒没有新增文字时改用 beam 3，并保持到当前窗口结束，提前校准停滞的草稿。窗口结束也使用 beam 3。
7. 检测中文字幕中的大段英文回显、短原文被扩写成整段上下文，以及长原文异常缩成几个字的情况，必要时改用更简洁的中文指令重试。达到生成长度上限的截断结果不会作为完整译文发布。旧片段暂时翻译失败时保留其原文和最近一次成功译文，让后续语音继续处理。这些检查不能代替完整的语义准确性评估。思考模式通过助手模板关闭，不把 `/no_think` 当作待翻译文本传给模型。
8. 对只含少数连词和人称代词的英语未完成短语，中文字幕采用保守的逐词映射，避免丢掉“我”等主语或凭空补出动词。含实义词的完整内容继续使用模型。

## 人声颜色与双人重叠

人声配色默认关闭，可在右键菜单中切换并自动保存。关闭时不下载或加载人声模型、不分析人声，也不计算词级时间戳。开启时才准备可选模型；关闭后立即恢复默认文字色，清空人声任务和身份信息，旧结果不能重新着色。

原字幕区域支持局部文字着色，不增加说话人窗口或姓名标签。开启后，识别保留词级时间戳，单独的人声线程处理同一份音频。pyannote ONNX 输出局部说话人活动和重叠范围，CAMPPlus 中英文声纹用于匹配身份。保留最多约 24 秒的音频上下文，跨静音分窗复核短句；用重叠的十秒分析窗覆盖上下文。局部轨道不直接作为全局身份，不把整个聚类中的所有话语混合提取声纹；同一窗的不同局部轨道不能匹配同一身份。同一份音频的历史匹配可作为锚点，降低跨窗变色。已检测到重叠的音频不用于新增或更新声纹。

人声确认前使用默认色，确认后按讲话片段分别翻译，在原段落内拼接着色；翻译仍参考前文。标签修订会更新相应翻译任务，未改变的片段复用缓存。仅窗口序号增加、文字和标签均未变化时，已有翻译仍可发布，避免不断被误判为过期而丢失颜色。缓存裁剪、换行和字号调整同步保留颜色范围。

检测到双人重叠时，把原始音频交给独立的后台修订队列。Conv-TasNet 将混音分成两路，单独的 CPU Whisper 分别识别，复用同一会话的身份注册表；不会把两路词按时间交错拼成一句。两路都得到非空识别文字且身份不同后，按各自标签更新原字幕中的对应段落。漏出到两路的相同长句会被拒绝；只识别出一路时保留原字幕。主识别继续运行，不等待修订任务；已有分离结果不会被后续混合草稿覆盖，较早的分离任务也不能覆盖较新的分离结果。较旧段落的修订会随后续任务保留，直到被发布或缓存淘汰。

每次开启在内存中最多保留八个人声身份，依次使用白、浅蓝、浅黄、浅绿、浅紫等颜色。切换目标语言和翻译模型不重置身份；关闭配色、重新连接或重启会重置。证据不足或超过身份上限时使用默认色。

首次开启准备约 50 MB 的人声与分离模型，固定版本并校验 SHA-256。分离器及第二个 CPU 识别模型仅在检测到重叠时加载；会增加 CPU 和内存占用，修订可能明显延后，共享 CPU 也可能影响总体速度。模型就绪后推理离线运行，不保存录音或声纹。

双人重叠处理属于初版，当前分离模型在英语 Libri2Mix 数据上训练。公开英文混音样本能恢复两路句子，但中文、短句、噪声及强重叠仍可能漏词、错词或无法分离；非空文字和不同标签不保证语义正确。暂不支持把三人以上同时讲话可靠地分别转写。人声检测漏掉的重叠仍可能被主识别合并。

这些时间是调度参数，并非总延迟承诺。首次输出还需要识别与翻译耗时；暂定译文会随后续原文修订，小模型仍可能错译。

## 字号与显示行数

右键可选择 12–48 pt 字号（默认 23 pt，支持自定义整数）和 1–10 行字幕（默认 4 行），立即重新排版现有字幕并保存到设置。引擎发布保留缓存，界面根据实际宽度和字号截取最近的视觉行；截断省略号也计入排版。屏幕高度不足时会限制实际可见行数，避免大字号时文字被窗口裁掉。

## Token 上下文预算（0.5.2）

4B 和 2B 默认均配置 2048-token 推理上下文。每次调用使用当前模型自己的分词器编码完整提示词，包括系统指令、角色标记、参考前文和原文；固定预留 256 个输出 token，另留 8-token 余量。正常与重试提示词都必须满足 `输入 token + 256 + 8 <= 实际 n_ctx`。

超限时从最旧的参考前文开始裁剪，尽量保留较新的完整前文；单条前文只保留合适长度的尾部。去除前文后当前片段仍放不下时，再按 Unicode 字符边界拆分，优先选择邻近的词或从句边界。拆分后的原文依次处理，已完成部分仍可先显示，剩余文字不丢弃。

预算通过后，编码得到的 token ID 直接交给 llama.cpp，不再让它对字符串重新分词。生成入口再次检查实际容量与完整输出预算，不依靠底层库自动缩短输出上限。缓存使用真正保留的前文作为键；重试同样受预算约束，并保持所选目标语言。

## 声音与隐私

Windows 使用 WASAPI 回环；Linux 使用 PulseAudio / pipewire-pulse 的默认输出 monitor 源，精确校验输出与 monitor 的对应关系。不使用实体麦克风；默认输出设备变化后自动重连。默认设备上的浏览器、视频播放器和会议软件声音会一起采集。单独路由到其他输出设备的声音、独占音频及受保护媒体不保证可以采集。

仅在缺少或损坏模型时联网下载权重，不上传声音、原文或字幕；推理在本机运行，不保存录音、原文或字幕历史。上下文和翻译缓存均在内存中。设置及诊断日志在 Windows 位于 `%LOCALAPPDATA%/SonoWeave`，Linux 位于 `${XDG_DATA_HOME:-$HOME/.local/share}/sonoweave`；日志包含组件状态与延迟，不主动记录实际字幕。打包程序下载到该目录下的 `models`，避免安装目录无写入权限；源码运行使用项目下的 `models`。旧发布目录旁已有的模型仍可复用。模型目录及所有 GGUF 文件均由 `.gitignore` 排除。测试产物存放在被 Git 忽略的目录，不随源码或发布包分发。
