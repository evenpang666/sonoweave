# 声屿 SonoWeave 0.3 验证记录

后续 0.3.1 的长时间实声测试发现了翻译缩水及英文回显问题，并做了修复与复测。最新结果及尚存问题见 [2026-10-22 测试记录](runtime-test-20261022.md)。下文保留 0.3.0 的历史测试数据，不代表全部准确性检查通过。

本次验证使用用户明确授权、持续在后台播放的真实外文声音，经默认扬声器 WASAPI 回环采集；没有用测试语音替代这一轮真实输入。环境为 Windows x64、Intel 24 逻辑处理器、RTX 4070 12 GB。

## 自动化测试

`python -m pytest -q`：**45 passed**。

覆盖持续原文缓存、当前草稿替换、跨句保留、滑动翻译窗口、上下文缓存命中、旧译文保留、尾部修订、错误片段不阻塞后续语音、英文回显重试、上下文过度扩写重试、缓存容量上限、强制分窗重叠去重、语言切换与过期结果取消，以及窗口只显示最近几行。

## 发布版本的真实声音测试

`tools/live_test.py --seconds 50 --label real-audio-v03-verified` 在模型就绪后继续测试 50 秒，从启动计共运行约 60.91 秒。采集从启动时就开始，模型准备阶段也会接收并缓存音频与识别结果。

| 指标 | 结果 |
| --- | ---: |
| 模型加载及预热 | 10.69 秒 |
| 字幕更新次数 | 85 |
| 原文缓存 | 1061 字符，5 段 |
| 译文缓存 | 348 字符，5 段 |
| 稳态窗口提交至字幕更新的中位耗时 | 0.141 秒 |
| 原文继续增长但字幕停滞的检测结果 | 0 秒 |

缓存会因识别修订而增减末尾文字，不要求字符数严格单调增长。测试中跨句前文持续保留，新内容继续追加；窗口仅显示最近最多 4 行，而不是把整段缓存铺满屏幕。具体汇总见 `live-cache-check.json`，其中不包含实际播放内容。

测试进程阻断 Python socket 连接，翻译和识别使用本机模型；**没有保存音频文件**。测试时的原文、译文及界面诊断仅放在被 Git 忽略的 `.cache/real-audio-v03-verified-test`，不随程序发布。

## 可执行文件

通过 `tools/verify_bundle.py --require-captions` 检查 `dist/SonoWeave/SonoWeave.exe`：验证界面输出、附带模型加载、实际系统音频初始化，并要求真实后台声音触发译文缓存更新。测试进程检查后关闭。

## 结论边界

0.141 秒是音频窗口已就绪后的处理耗时，包含识别、排队和翻译，不包含分窗等待、播放器自身缓冲或模型首次加载时间；不能理解为声音发生到字幕出现的总延迟保证。

这次实际声音测试及回归用例证明缓存链路可以持续更新，并不能证明小模型在所有口语、俚语、专业术语和语种上都准确。识别与译文仍可能有错误，末尾校准也可能改变先前译法。旧片段暂时失败时可能保留上一版译文或暂缺该段，但不应阻塞后续语音。

旧版 `streaming-gpu.json`、`streaming-cpu.json` 与 `offline-check.json` 是公开测试样例的历史诊断；本次实时缓存行为以 `live-cache-check.json` 和上述发布版本测试为准。
